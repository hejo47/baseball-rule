## 1. 왜 새 기능이 필요한가

- 지금 앱은 야구규칙, 리그 규정, 규약에서 조항을 찾아 설명해 준다.
- 그런데 이것만으로는 "규칙집 PDF를 직접 찾아보면 되지 않나?"에 답하기 어렵다. 조항을 더 잘
  찾는 건 PDF 검색과 정도 차이일 뿐이라, 굳이 이 앱을 쓸 이유가 약하다.
- 검색은 이미 쓸 만하다(시험 문항 전부 정답이 AI에게 넘어간다). 검색을 더 다듬어도 사용자가
  느끼는 차이는 작다.

**결론:** 다른 서비스가 하지 않는 일, 즉 **규정을 실제 선수와 경기에 적용해 주는 것**으로 넓힌다.

## 2. 떠올린 방향과 고른 것

| 방향 | 판단 |
|---|---|
| 선수 기록 조회(타율, 홈런 등) | 하지 않는다. 네이버, 스탯티즈, KBO 앱이 이미 잘한다. |
| **규정과 선수 데이터 잇기** | **먼저 한다.** "○○ 선수 FA 언제 돼?", "부상자 명단에서 언제 돌아와?", "외국인 선수 교체 몇 번 남았어?" |
| 실제 판정 해설 | 나중에 한다. "어제 그 장면은 왜 아웃이야?" 문자 중계 같은 경기 데이터가 필요해 더 어렵다. |

선수 데이터 잇기를 먼저 고른 이유:

- 시즌 중과 스토브리그에 실제로 자주 나오는 질문이다.
- 근거 규정은 이미 다 들어 있다(규약의 FA·외국인선수 조항, 리그 규정의 부상자 명단).
  없는 건 선수 데이터뿐이다.

## 3. 무엇이 필요한가

| 질문 | 근거 규정 | 필요한 선수 데이터 |
|---|---|---|
| FA 언제 돼? | 규약 제162조 | 시즌별 현역 등록일수, 첫 등록 연도, 대졸 여부, 다년계약 기간 |
| 부상자 명단에서 언제 돌아와? | 리그 규정 제14조-3 | 등재일과 기간, 그 시즌 등재 이력 |
| 외국인 선수 교체 몇 번 남았어? | 외국인선수 고용규정 제9조 | 구단별 그 시즌 해지·추가등록 이력 |

- 부상자 명단이 가장 작다(등재일과 기간만 있으면 계산된다). FA는 몇 년 치 데이터가 필요해 가장 크다.
- 숫자 계산은 코드가 하고, AI는 결과와 근거 조항을 받아 설명만 한다. 작은 모델은 조항을 상황에
  대입하는 걸 자주 틀린다.

## 4. 선수 데이터를 어디서 구하나 (조사 결과)

**공개 사이트에서 자동으로 가져오는 건 안 된다.**

- **KBO 공식:** robots.txt에 "사전 승인 없이 자동 수집 금지". 이용약관 제14조도 자동 수단으로 선수
  통계를 대량 수집하거나 재배포·2차 가공하는 것을 금지한다(사전 서면 동의나 공식 API가 있으면 예외).
  제17조는 상업적 사용 금지(사전 동의 시 가능).
- **네이버 스포츠:** 검색엔진 외 차단. **스탯티즈:** 봇 차단.
- **AI가 페이지를 읽어서 DB에 넣는 것도 자동 수집이라 안 된다.**
- 저작권법 제93조: 개별 사실은 보호 대상이 아니지만, 반복적·체계적으로 가져가면 데이터베이스의
  상당 부분을 복제한 것으로 본다.

## 5. 남은 길

| 방법 | 장점 | 단점 |
|---|---|---|
| ① 사용자가 상황(등재일, 기간 등)을 말하면 규정대로 계산 | 문제없음. 지금 바로 가능 | 사용자가 사실을 알고 있어야 한다 |
| ② 네이버 검색 API로 뉴스를 받아 사실만 뽑기 | 허용된 경로 | 뉴스가 모든 변동을 다루지 않고, AI가 잘못 읽을 수 있다 |
| ③ KBO·스포츠투아이에 공식 API 승인 문의 | 정식, 데이터가 정확 | 승인까지 시간이 걸리고 안 될 수도 있다 |

문의처: 스포츠투아이 `marketing@sports2i.com`, KBO 사무국 02-3460-4600.

### 5-1. 스포츠 전문 언론과 X 전문 계정은? (2026-10-23 조사)

**스포츠 언론사 사이트를 직접 긁기: 권하지 않는다.**

- robots.txt로 막지는 않는다. OSEN, 스포츠서울, 엑스포츠뉴스, 스포티비뉴스는 일반 봇을 허용한다.
  MK스포츠는 AI 봇(GPTBot, ClaudeBot 등)만 막는다.
- 하지만 저작권 규약이 막는다. OSEN 저작권 규약 제4항: "허가없이 … 인터넷 및 데이터 베이스를
  비롯한 각종 정보서비스 등에 사용하는 것을 금지", "전자매체로 복사, 재사용을 위한 저장은 허가되지
  않습니다". 다른 언론사도 대개 비슷하다.
- 사실 자체("○○ 선수 10일짜리 부상자 명단 등재")는 저작권 보호 대상이 아니다(저작권법 제7조).
  그래도 남의 사이트를 반복적·체계적으로 긁어 내 서비스에 쓰면 부정경쟁방지법 제2조 제1호 (카)목
  (성과물 무단 사용)으로 민사 책임을 질 수 있다. 잡코리아-사람인, 야놀자-여기어때 사건에서 손해배상이
  인정됐다(형사는 무죄).
- **같은 뉴스를 받는 허용된 길은 네이버 검색 API다.** 제목, 요약, 링크를 주니 사실만 뽑고 원문으로
  연결하면 된다(5절 ②와 같다).

**X 전문 계정을 긁기: 안 된다. 공식 API로 받는 건 된다(유료).**

- 긁기: X 이용약관이 사전 서면 동의 없는 자동 수집을 금지한다. robots.txt도 검색엔진 외 전부
  `Disallow: /`. 2024-11 약관부터 위반 시 24시간 안에 글 100만 개당 1만 5천 달러 배상을 정해 두었다.
- 공식 API: 2026-02부터 정액 없이 쓴 만큼 낸다. 글 하나 읽기 0.005달러(월 1만 개면 약 50달러),
  월 200만 개 상한. 무료는 없다.
- API 조건: X 글로 AI 모델을 학습시키는 건 금지(우리는 학습이 아니라 사실 추출이라 해당 없음).
  AI 자동 답글 봇은 별도 승인이 필요하다(우리는 답글을 달지 않는다).

**둘 다 공통으로 남는 문제:** 기자나 전문 계정의 글은 공식 발표가 아니라 틀리거나 바뀔 수 있다.
답변에 "○○ 보도 기준"처럼 출처와 날짜를 붙이고, 계산 결과는 참고용이라고 밝혀야 한다.

## 6. 지금 상태와 다음 걸음

- **정했다(2026-10-23):** ②(네이버 뉴스 검색 API)로 시작한다. 사용자가 날짜를 찾아 와야 하는
  ①만으로는 너무 번거로워서 쓸 이유가 없다. 사용자는 **선수 이름만** 말하게 한다.
- ③(공식 데이터 문의)은 개발과 별개로 넣어 둔다. 뉴스가 놓치거나 잘못 읽는 문제를 없애려면 결국 필요하다.
- 순서: 부상자 명단 → 외국인 교체 → FA.

### 6-1. 부상자 명단 질문의 흐름

미리 모아 두지 않고 **질문이 들어올 때 그 선수만** 찾는다.

1. 사용자: "○○ 언제 돌아와?" (선수 이름만)
2. 네이버 뉴스 검색 API로 `선수명 부상자 명단`을 찾는다
   (응답: 제목, 요약, 원문 링크, 날짜. 하루 25,000회 무료).
3. 요약에서 등재일과 기간(10·15·30일)을 뽑고, 코드가 규정대로 복귀 가능일을 계산한다.
4. **확인 질문 없이 바로 답한다.** 출처와 날짜, 원문 링크를 붙인다.
   "10월 20일 OSEN 보도 기준, 10일짜리 등재라 10월 29일부터 돌아올 수 있습니다."
5. 기사가 없거나 틀렸을 때만 사용자가 날짜와 기간을 고친다.

걱정되는 점(확인 필요):

- 기사가 "엔트리 말소"라고만 쓰고 부상자 명단인지 밝히지 않을 때가 있을 수 있다.
  얼마나 자주 그런지 실제 기사로 재 봐야 한다. 그럴 땐 "부상자 명단 여부는 기사에 없음"이라고 밝힌다.
- 등재 뒤 기간 연장이나 조기 복귀 기사를 놓치면 답이 틀린다. 가장 최근 기사를 우선한다.
- 사람이 KBO 공식 사이트에서 등록·말소 현황을 보고 알려 주는 건 문제없다.
  앱이 그 페이지를 대신 읽는 건 안 된다(4절).
